1. What it is

RigApp is a desktop and web app for running OpenRig rigs. A rig is a project, its seats are threads, and you talk to the rig through its lead seat, like a Claude Code Project. It looks and feels like T3 Code: projects and threads on the left, the chat in the middle, details on the right. It is for one person running several AI agents at once on Windows or Linux. It is not an agent runner of its own, it does not change OpenRig, and it is not a copy of Operant: it stays lean so seats use no more tokens than plain Claude Code.

2. Pillars

Every feature must serve at least one.

  1. One place to run a rig. Everything you do to a rig or seat works from RigApp without a terminal. Example: rig up, snapshot and restore from the project menu.
  2. Shows what needs you. You see at once which seat waits, failed or finished, and act in one click. Example: Overview with Approve on the row.
  3. Lean on tokens. RigApp adds nothing to a seat unless you turn it on, and shows the cost when you do. Example: Hindsight on for one pod only.
  4. Honest about OpenRig. Every call is a real route; gaps are listed and filled with visible stopgaps, never fake data. Example: the setup screen says exactly what is missing.

5. How a milestone runs

  1. Start: Claude writes docs/milestone-N-guide.html (goal, parts, out of scope) and asks doole every question it needs in one bundle.
  2. doole approves the guide. Claude marks it "In progress: approved" with the date here and in CLAUDE.md.
  3. Claude builds in small steps. After each step, its test steps go in the guide.
  4. End: one review checklist in the guide for doole (about 30 minutes). Fixes from it jump the queue.
  5. Close: Claude marks it done here and in CLAUDE.md, ticks its items in section 4, updates docs/systems.md, records decisions in section 3 and docs/design.md, and adds a line to section 8. Then reports the path to run the app, what was verified and what was not, screenshots, and any OpenRig gaps found.

6. Where ideas go

  • Fits a planned milestone: add it to that milestone in section 7.
  • Needs something not built yet: park it under the milestone that builds that thing.
  • Serves no pillar: park it under "Maybe never" with one line on why.
  • Changes a settled decision: ask doole; it is not decided until they say so.
  • Never slip it into the milestone in progress, however small.

After M4

  • Phone access to the same server (the layout already works at 390 px). (from the prompt, 2026-10-29)

Maybe never

  • Running the OpenRig daemon natively on Windows (via psmux): changes OpenRig itself, which RigApp does not do.
  • Operant's Orchestrator Mode, learning and helper system: the lead seat already does this through OpenRig, and it costs tokens.
