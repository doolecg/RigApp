Milestone 1 "Projects and threads"

State: In progress: approved 2026-10-29

Read this first
  • Goal: Open RigApp, see every rig as a project with its seats as threads, talk to the lead and to any seat, answer approvals and see what needs you, all against a real rig in WSL.
  • Out of scope: Graph and terminal (M2), spec editing and lifecycle (M3), updater and packaging (M4), seat tools (M5).
  • Approved 2026-10-29 ("Start building"), with Claude's recommended answer to each question in section 2. The terminal socket stays off until you turn it on yourself; RigApp works without it.
  • To change anything, write in the notes box under it, press Copy my notes, and paste to Claude.

1. Parts

  • Monorepo: pnpm workspace with apps/server, apps/web, apps/desktop and a small packages/contracts for the message types. T3 Code layout.
  • Daemon link: the server finds OpenRig (WSL on Windows, local on Linux, or a set address), checks /healthz, follows /api/events and /api/activity/events, and re-reads /api/ps and seat lists on each change.
  • Setup screen: clear checks for WSL, tmux, the rig CLI and the daemon, with exact steps. Installs nothing.
  • Layout: resizable sidebar (projects, pods, seats), chat column, collapsible right panel (seat details). The search box opens Ctrl+K, so it comes with the command palette; Files comes with Chat; New project moved to M3 (2026-10-29).
  • Chat: a Files tab in the right panel, and messages read from each seat's session file (Claude Code first, then Codex and Pi), collapsible tool cards, diffs, status dot per thread, unread markers.
  • Approvals and interrupt: a card when a seat is waiting on a permission prompt, Approve and Deny, and Stop. Answers are sent as keys (stopgap, see systems.md gaps 2 and 3).
  • Composer: multiline, Enter to send, Shift+Enter for a new line, @seat to direct a message, / rig commands. Sends through /api/transport/send.
  • Overview: every seat that waits, errored, finished or is working, with one-click actions.
  • Command palette: Ctrl+K for every action and every seat.
  • Project kit and repo basics: LICENSE (MIT), README with Disclaimer and credits, Main Run and Dev Run configs.
  • Tests: Vitest for the daemon client with recorded real responses; Playwright for open a project, open a thread, send a message, approve a prompt.

3. How to test each step

Step: Setup screen

  1. Run the Dev Run config in IntelliJ. It installs, builds and opens http://127.0.0.1:7480 in your browser.
  2. The sidebar shows kernel (Advisor, Operator, Queue) and starter (Dev), with lead marked and a harness label on each seat. Click a seat: its details show on the right (widen the window if the right panel is hidden).
  3. In Ubuntu run rig daemon stop (your seats keep running): within a few seconds RigApp shows the setup screen, with WSL2, tmux and the CLI ticked and the daemon crossed.
  4. Run rig daemon start and press Check again: the sidebar comes back with kernel and starter.
  5. Stop RigApp with the red Stop button in IntelliJ.

Step: Layout (panels)

  1. Run & "E:\REPOS\AI TOOLS\RigApp\tools\dev.ps1" in PowerShell and open http://localhost:7481.
  2. Drag the right edge of the sidebar: it gets wider or narrower (220 to 420 px). Double-click the edge to reset it. Reload: the width stays.
  3. Press the panel button next to RigApp: the sidebar hides; the same button at the top left brings it back.
  4. Press the panel button at the top right: the seat details hide and come back. Reload: both choices stay.
  5. Make the window narrow (or press F12, then Ctrl+Shift+M for phone size 390): a menu button opens the sidebar over the page; picking a seat closes it. The top right button opens the details over the page; X or Esc closes it.

Step: Chat (reading)

  1. Run & "E:\REPOS\AI TOOLS\RigApp\tools\dev.ps1" and open http://localhost:7481.
  2. Click build under starter: its whole conversation shows, with each tool call as a folded card. Edits show their change open, in red and green, with +/− counts.
  3. Click any folded card: it opens to show the command and what came back.
  4. Click lead under kernel. In Ubuntu, send it a message with rig send advisor-lead@kernel "Say hello in one line": within a couple of seconds your message and its reply appear without reloading.
  5. Click human under kernel: it says it is a terminal seat with no chat.

4. Review checklist (about 30 minutes)

  • kernel and starter show in the sidebar, seats grouped by pod, with the right harness labels.
  • Send a message to the lead: it arrives in the seat and its reply streams into the chat.
  • Make a seat ask for permission: the card appears in the thread and in Overview; Approve works.
  • Stop interrupts a working seat.
  • Ctrl+K finds any seat and any action.
  • Light theme and phone width (390) look right.
