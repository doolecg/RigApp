3. How to test each step

Step: Specs

  1. Run & "E:\REPOS\AI TOOLS\RigApp\tools\dev.ps1" and open http://localhost:7481.
  2. Open build under starter and click Specs: rig.yaml and CULTURE.md open in an editor. Click Validate: OpenRig says the spec is valid.
  3. Change a word, click Review changes to see the change in green and red, then Save. RigApp saves through OpenRig, which refuses if the file changed on disk in the meantime. The rig uses it the next time it starts.
  4. Open lead under kernel: its spec is built into OpenRig, so it shows read-only, with the reason.

Step: Rig up and down, snapshots, usage

  1. Open any seat, then the Rig tab in the right panel: the Claude weekly and 5-hour windows, each seat's context use, and the snapshot list.
  2. Rig up (on a stopped rig) first shows OpenRig's plan for each seat; nothing starts until you press Rig up in that box. Rig down asks first and offers a snapshot.
  3. Hover a snapshot and press Restore: it explains what happens and asks first.

Step: New project and search

  1. Click New project in the sidebar, pick a team, type a folder (a Windows path like E:\REPOS\MyApp works) and press Check with OpenRig. Start project is only possible after OpenRig says it can start it.
  2. Press Ctrl+K and type three or more letters that appear in a seat's screen: matches show under "In seat logs". OpenRig matches them exactly, capitals included.
  3. Tests: pnpm test:e2e includes all of the above except actually starting, stopping or restoring a rig.

4. Review checklist (about 30 minutes)

  • Edit kernel's rig.yaml, see the diff, save, and the change is live after rig up.
  • Rig down asks first and offers a snapshot.
  • Restore from a snapshot on the timeline works.
  • Usage shows real numbers for a Claude seat.
